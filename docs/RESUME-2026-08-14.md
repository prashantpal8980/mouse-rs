## The bug worth knowing about

`serve_request` read the whole file into an **unbounded** channel in a tight loop,
while `bulk_pump` drained it slowly and deliberately (pacing, and pausing entirely
while the pointer is crossed). The queue therefore *became* the file — copying a
4 GB ISO would have held roughly 4 GB in memory, on the sending machine.

The plan's §8 cost table says a 4 GB ISO costs ~4 MB and about 1% of a core. That
was true of the receiving side and false of the sending side, and the sending side
is the one under test when a large file is copied from Windows.

Fixed by `mouse_core::bulk::BulkQueue`: a shared counter the sender adds to and the
lane credits back only once bytes are really written. The sender waits while it is
full. Because waiting must not happen on the clipboard thread — which has to keep
polling the clipboard and answering the panel — each blob is now served by its own
short-lived thread carrying a cancel flag.

That restructure is also what makes **cancel** real rather than cosmetic.

## Round two (same day): diagnostics, after the first hardware test

The owner copied a 3.3 GB `.mkv` from Kali and Explorer's Paste stayed greyed. Diagnosis
was guesswork, because half the evidence was on a machine I cannot read and the half I
could read said nothing about *why*. That was the real defect.

- **Both machines ship their logs** to a collector named in `log_upload_url` (`logship.rs`),
  every 30s and once on exit, tail-capped at 4 MB. Verified working from Kali.
- **Every auto/ask decision states its reasoning**, and the waiting case says what it is
  waiting for and what would change it. `PUBLISHED files to the …clipboard` on both
  platforms names the paths actually handed over — "transferred but Paste is greyed" and
  "never transferred" used to look identical.
- **Images can be pasted into a file manager** via an "as file" button: neither Explorer
  nor Thunar can paste pixels, so the image is written out as a `.png` and *that* is put
  on the clipboard. Per entry, not always — publishing the file replaces the pixels and
  would break pasting into a browser, which is the common case.
- **Real Windows toast** through PowerShell's built-in AUMID, so no installer is needed.
  A waiting file was invisible on Windows, which made consent undiscoverable.
- **`ingest` no longer copies files larger than the whole cache budget** — a 3.3 GB copy
  against a 2 GB budget wrote 3.3 GB and the next eviction deleted all of it.

**What the first test actually established:** the send side works (`files copied here;
telling the peer count=1 bytes=3307226993`), and Windows never requested the bytes — so
consent was never given and Paste was correctly greyed. Not a transfer bug. A
tell-the-user bug.

**Still unproven:** that a file completes end-to-end and lands on the Windows clipboard.
A 45-byte probe was pushed from Kali at 08:20 UTC; the Windows log will show whether it
was fetched and published.

160 tests, clippy clean both targets.

## Hard-won rules — do not relearn these

- **A tested function nothing calls is not a feature.** Caught again this session:
  `progress_of` was written, compiled, and had no caller. Deleted rather than shipped.
- **Never add a setting the code does not read** (R16), and never leave one the code
  reads *only at startup* out of the restart prompt — that is the same defect wearing
  a disguise.
- **Check the claim, not the code you remember writing.** The §8 memory table read as
  true because the receiving side matched it.
- **Never inject synthetic input while control is on the peer** — it gets forwarded.
  Kali is the *client*, so local synthetic input is not captured.
- **Never click the panel with raw screen coordinates.** `xdotool mousemove --window`
  plus a focus check.
- **Kill test instances by PID.** `pkill -x mouse-rs` would take the owner's live
  session with it.
- **The consent prompt must never steal the foreground.** Windows withholds
  `WH_KEYBOARD_LL` while our own process owns the foreground window.
- `export RUSTFLAGS="-L /home/kalip/mouse-rs/.xdo-shim"` for every Linux build.
- `cargo build -p mouse --no-default-features` overwrites the GUI binary at the same
  path. Rebuild with default features afterwards.
