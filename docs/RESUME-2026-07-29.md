## Build gotcha that will bite again

The Linux GUI links `libxdo` through the tray, and only the **runtime** `libxdo3` is
installed — there is no `libxdo-dev`, so no `libxdo.so` symlink and the final link fails
with `unable to find library -lxdo`. The repo carries its own shim; every Linux build needs:

```sh
export RUSTFLAGS="-L /home/kalip/mouse-rs/.xdo-shim"
```

Without it `cargo build`/`cargo test` fail at link time only — `cargo clippy` and
`cargo check` still pass, which makes it look like a packaging problem rather than a
missing flag. `scripts/package.sh` recreates the shim itself, so packaging is unaffected.

## Testing traps worth remembering

- **Never test the window ✕ with `xdotool windowclose`** — it *destroys* the window instead
  of sending `WM_DELETE_WINDOW`, which fakes two convincing failures (a wgpu
  `Surface::configure` panic on Vulkan; a stranded process on GL). Use **Alt+F4** or click
  the decoration. This cost a wrong bug report and a needless "fix" that was reverted.
  Full note in `TESTING.md` §6b.
- **Driving the GUI by absolute screen coordinates on the live desktop is fragile** — the
  maximized terminal keeps taking focus and clicks land in the wrong window. Either verify
  `xdotool getmouselocation` reports the target window before every click (and abort if
  not), or move the window to an empty workspace. A second Claude session runs on that
  desktop, so a stray click is not harmless.
- `import -window <id>` can return a stale frame for an unfocused GPU-rendered window;
  `xwd -id <id>` was reliable.
