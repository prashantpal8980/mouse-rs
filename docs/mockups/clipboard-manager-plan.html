Clipboard manager — the plan

Turning the clipboard from a list you can only look at into one you can actually use, and letting it carry files of any size without your mouse stuttering.

1 · the correction

You were right — it was meant to be a manager

The requirement was a clipboard manager. What got built was a log with a manager's name on it. That's a mistake in the build, not a change in scope, and the requirements doc now says so.

Two things make it view-only today:

  • The rows aren't buttons. They're plain boxes with no click handler. It isn't a broken button — there was never a button.
  • Images aren't saved. When an image syncs, we store the text [image 800×600, 240 KB] and throw the picture away. So there's nothing to paste back even if you could click it.

Which means the fix isn't "make it clickable". We have to change what gets stored first.

2 · your question

Does Windows compress images? Yes.

Windows saves the compressed PNG version, not the raw picture. It has no choice — the raw form is far too big.

A 1920×1080 screenshot as raw pixels is 8.3 MB. Windows' own limit is 4 MB per item, so the raw form wouldn't even fit. Compressed as PNG the same screenshot is around 400 KB — about 20× smaller. Without compression, Win+V would reject nearly every screenshot you take.

We already compress to PNG, so that part of our design is right.

The part worth knowing: Windows can't do files at all

Copy setup.exe in Explorer and press Win+V — nothing. Windows' clipboard history holds text, HTML and images only.

So "copy any file to the other machine" isn't us catching up to Windows. It's something Windows doesn't do — which matters, since you plan to sell this.

3 · the mouse-freeze problem

Why a big file would stutter your mouse

Right now everything travels down one road — mouse, keyboard and clipboard share a single connection. And that road is one lane, single file. Nothing overtakes.

Today one big file — everything waits behind it ✕ Your mouse packets are tiny, but they're stuck in the queue.
The fix ✓ Mouse and keyboard get their own road. Always clear.
files go on a second road, at a polite speed

A second connection means file data physically cannot get in front of your mouse. But both roads still share one Wi‑Fi signal, so we also slow the file lane down when it starts crowding things — like leaving a gap in traffic.

We already have the speedometer

The app sends a heartbeat between machines and measures how long the reply takes. That number is how laggy your mouse feels. So: if it starts rising, slow the file transfer down. If it stays flat, speed up.

It adjusts itself on Ethernet, Wi‑Fi or a weak hotspot with nothing for you to configure.

This is already a small bug today — your Ethernet is hiding it

Copying a large image right now blocks the road for about 1 second on a hotspot. On your gigabit cable it's 50 milliseconds, which is why you've never felt it.

Worth testing once on the hotspot before we build — it tells us whether this is urgent or just correct.

4 · how files get stored

Small things get copied. Big things get fetched.

Your instinct was right. The only thing I'd change is what happens after you use a big file.

under your limit
Copied straight over

Text and images. They travel with the copy, automatically, and sit in your history ready to paste — even if the other machine is switched off.

over your limit
Fetched when you want it

Only the details cross at first — name, size, where it lives. The entry shows up instantly and costs almost nothing. The actual file moves when you say so.

The one change to your idea

You suggested keeping the file's path and re-reading it from Windows each time. That works — until the file moves, and then the entry is dead forever.

So: use the path to fetch it once, then keep our own copy. After the first use the entry is ours, and you can delete the original freely. Best of both.

We also name our copies by a fingerprint of their contents, which gives us two freebies: copy the same ISO twice and it's stored once, and if the other machine already has a file, we skip the transfer entirely — a 100 MB "copy" finishes instantly.

5 · your deleted-file question

What the entry says when the file is gone

Every entry always shows you honestly where it stands:

ReadyWe have it. Paste instantly, no network needed.
On the laptop104 MB — click to bring it over.
Fetching…Progress bar. Can be cancelled, resumes if the link drops.
Not there any moreDeleted or moved. We say “no longer at the recorded path” — because without scanning the whole disk we genuinely can't tell which, and won't pretend to.
File has changedStill there, but different from when you copied it. We ask before pasting a different version.
Laptop is offNot an error. Greyed out, works again on reconnect.
6 · the prompt

"This file is big — send it across?"

  • Under 1 MB (your setting): silent. It just works, like text does now.
  • Over it: the entry appears straight away, and you get asked once — Send now / Not now / Always allow this size.
  • Answer whenever. Ignoring it loses nothing; the entry waits.
  • Transfer runs in the background with progress and cancel. It takes as long as it takes — but the mouse stays smooth the whole time, which is the actual promise.

This popup must not grab focus — and that's not a style choice

A normal pop-up dialog would bring the keyboard bug back. Windows stops sending us key presses whenever our own window is in front — that was the exact cause of the bug we fixed on 31 July.

A window that jumps in front the moment you copy a file would trigger it every time. So it's a quiet banner in the panel plus a tray notification. Never a focus-stealing dialog.

Everything is configurable — in two levels

There are enough clipboard settings now that dumping them all on one page would be worse than having fewer. So they split the way serious software splits them: Basic is what most people touch, Advanced is behind a toggle and holds the rest. Nothing is hidden from you — it's just not all shouting at once.

One thing the software should still tell you

100 entries × 256 MB each is a 25 GB history. That's yours to choose — but the settings page should show the total as you change it, so you see the cost while deciding rather than finding out later.

8 · the numbers

What it actually costs

The good news: big files are cheap for your computer. They stream through in small pieces instead of being loaded whole, so a 100 MB file and a 4 GB ISO cost the same memory.

What you copyMemory usedEffort for your PC
Any texta few MBnothing
A screenshot~20 MB brieflya fraction of a second
A 4K screenshot~70 MB brieflyabout a second
A 100 MB file~4 MB~1% of one CPU core
A 4 GB ISO~4 MB~1% of one CPU core

So your computer isn't the bottleneck — the network is. How long a big file takes is simply how fast your connection is:

One current setting that's too generous

We currently allow images up to 4096×4096. One copy of that size briefly eats 67 MB and ties up a CPU core for ~3 seconds, with no warning. It should be lower by default — and it should be one of your settings, not a fixed number in the code.

9 · build order

Five steps, each useful on its own

  1. Make the history usableClick any entry to re-copy it. Actually save images. Add your settings and pinning. This alone fixes what you reported.
  2. Add the second roadA separate connection for big data, slowed automatically when it would affect your mouse. Also fixes the hidden stutter that exists today.
  3. Teach it to read and write filesCopy a file on either machine and see it appear correctly in the history. Local only at this stage.
  4. Connect the twoFetch on click, progress, the "file is big" prompt, and all the entry states including deleted and moved. This is where it becomes the thing you asked for.
  5. Folders, and loggingCopy whole folders. And log clipboard activity — right now it logs nothing at all, so any failure is impossible to diagnose.
10 · the rule

No decision gets taken away from you

Both of the questions I was going to ask you — keep history after restart? and skip the prompt when the transfer will be quick? — are now settings instead of decisions. That's the correct answer, and it's the rule for the whole feature:

  • If it's a trade-off, it's a setting. Speed against safety, convenience against disk space, quiet against control — all yours.
  • The software states the cost, it doesn't refuse. Turning on history-after-restart says what it means for your privacy right there in the panel. Setting a huge image limit shows what it will cost. Then it does what you said.
  • Sane defaults, so it works out of the box for anyone who never opens Advanced.

The only things left non-configurable are the ones where a choice would break the program rather than tune it — the popup never stealing focus, files only ever landing in our own cache folder, and input always outranking file transfer.
