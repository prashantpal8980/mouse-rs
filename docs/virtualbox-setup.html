VirtualBox test setup

For the Linux ↔ Linux and Windows ↔ Windows tests (B33). Everything happens on Kali. Nothing needs installing on the laptop.
Written 26 Oct 2026 · total time about 2 hours, mostly waiting

1. How the testing works

Linux ↔ Linux
Kali (the real machine) ↔ a Linux Mint VM running on Kali.
Windows ↔ Windows
The laptop (the real machine) ↔ a Windows 11 VM running on Kali.

The VMs use a Bridged network, so they join your network as if they were separate computers, each with its own IP address. mouse-rs in a VM therefore behaves exactly as it would on a customer's second PC.

A VM is good for checking that things work: connecting, crossing, keys, copy/paste. It is not good for judging smoothness. Judge that only between the real Kali and the real laptop.

Can both OSes share one virtual disk? No. Each OS needs its own disk. But dynamically allocated disks only take the space that is really written, not their full size, so the two together stay under 40 GB. The ISOs can be deleted after installing.

The hard disk spins at 5400 rpm, so Windows will boot slowly (1–2 min). That's fine for testing. Close Chrome while installing Windows to keep RAM free.

AGive the hard disk a fixed place that mounts at every boot

Right now it only mounts when you click it, at a path with a space in it. A VM whose disk isn't mounted shows as "inaccessible". Make it permanent at /mnt/data:

sudo mkdir -p /mnt/data
echo 'UUID=7C11-146B /mnt/data exfat defaults,uid=1000,gid=1000,nofail 0 0' | sudo tee -a /etc/fstab
sudo umount "/run/media/kalip/New Volume"
sudo mount -a
mkdir -p /mnt/data/VMs/iso
df -h /mnt/data

Line 2 tells Linux to mount this disk (identified by its ID, 7C11-146B) at /mnt/data at every boot, owned by you. nofail means Kali still boots normally if the disk is ever missing. The last line should show about 771 GB free.

3. Install VirtualBox

sudo apt update
sudo apt install -y linux-headers-$(uname -r) virtualbox virtualbox-qt
sudo usermod -aG vboxusers kalip
sudo modprobe -r kvm_intel kvm
sudo modprobe vboxdrv
  • linux-headers: VirtualBox builds a small kernel driver for your exact kernel (6.19), and it needs these files to do that.
  • usermod: lets you use VirtualBox without root. It takes effect after you log out and back in.
  • modprobe -r kvm_intel kvm: Kali loads KVM (Linux's built-in virtual machine system) at boot. KVM and VirtualBox can't both use the CPU's virtualization at the same time; with KVM loaded, VirtualBox fails with "VT-x is being used by another hypervisor". This line unloads KVM. You have to repeat it after every reboot, before starting a VM (or see the fix in section 9).
  • modprobe vboxdrv: loads VirtualBox's driver. No output means it worked.
If it says "Key was rejected by service": Secure Boot is on, and it blocks unsigned drivers. Tell me before changing anything.
Don't install the "Extension Pack". It isn't needed for these tests, and its license (PUEL) is only free for personal use. mouse-rs is a commercial product.

5. VirtualBox: one setting first

Open VirtualBox → File → Preferences → General → Default Machine Folder → /mnt/data/VMs. Every new VM now goes on the hard disk.

6. Create the Windows 11 VM

  1. New → Name Win11-test · ISO Image: the Windows ISO · tick Skip Unattended Installation.
  2. Hardware: Base Memory 4096 MB · Processors 4 · Enable EFI ticked.
  3. Hard disk: Create a virtual hard disk, 64 GB, Pre-allocate Full Size unticked.
  4. Finish. Then Settings (before the first start):
    • System → Motherboard: TPM 2.0 (Windows 11 refuses to install without it) · Secure Boot ticked.
    • Display: Video Memory 128 MB.
    • Network → Adapter 1: Attached to Bridged Adapter, Name eth0.
    • General → Advanced: Shared Clipboard Disabled, Drag'n'Drop Disabled (see section 8).
  5. Start → press a key when it says "Press any key to boot from CD".
  6. Setup: "I don't have a product key" → Windows 11 Pro → Custom install → the empty disk → Next. About 20–30 min.
  7. Local account without Microsoft sign-in: on the network/sign-in screen press Shift+F10, type start ms-cxh:localonly and press Enter. Create user test. (On older builds the command is OOBE\BYPASSNRO.)
  8. When on the desktop: Devices → Insert Guest Additions CD image → open the CD in Explorer → run VBoxWindowsAdditions.exe → reboot. This gives correct screen resizing.

Why eth0 for Windows: the cable between Kali and the laptop is where the laptop hands out 192.168.137.x addresses. A VM bridged to it gets one of those, reaches the laptop directly, and can download mouse-rs from Kali the same way the laptop does.

7. Create the Linux Mint VM

  1. New → Name Mint-test · ISO: the Mint ISO · Skip Unattended Installation.
  2. Memory 3072 MB · Processors 2 · disk 30 GB, not pre-allocated.
  3. Settings: Display 128 MB · Network Bridged Adapter → eth0 · Shared Clipboard and Drag'n'Drop Disabled.
  4. Start → Mint opens a live desktop → double-click Install Linux Mint → defaults → "Erase disk and install" (this only erases the virtual 30 GB disk) → user test. About 10–15 min.
  5. After the reboot, in Mint's terminal: 
    sudo apt update && sudo apt install -y virtualbox-guest-x11 libgtk-3-0 libayatana-appindicator3-1
    The first package does the VM screen resizing; the other two are what the mouse-rs window needs on any Linux.

8. Settings that matter for mouse-rs tests

SettingWhy
Shared Clipboard: Disabled
Drag'n'Drop: Disabled		VirtualBox has its own copy/paste between Kali and the VM. If it is on, a paste could come from VirtualBox and not from mouse-rs, and the copy/paste test would prove nothing.
Mouse integration OFF when the VM is the server
(Input → Mouse Integration, or Right Ctrl+I)		With integration on, the VM gets the pointer's absolute position from VirtualBox, and the edge-crossing capture can't work. Off = the VM sees real mouse movement, like a real PC. Click into the VM to give it the mouse; Right Ctrl gives it back to Kali.
Mouse integration can stay ON when the VM is the clientThe VM is only receiving; just keep Kali's own pointer away from the VM window.
Run the VM full screen (Right Ctrl+F)The screen edges of the VM are then the real edges, so crossing works the same way as on a real PC.
Windows Firewall prompt the first time mouse-rs runsClick Allow (private networks). Otherwise the other machine can't find it.
Only one VM running at a time15 GB of RAM: Windows 4 + Mint 3 + Kali is fine, but each test only needs one VM.

9. Avoid repeating the KVM line after each reboot (optional)

echo 'blacklist kvm_intel' | sudo tee /etc/modprobe.d/no-kvm.conf

KVM is then never loaded at boot. Nothing on this machine uses it today. Undo by deleting that file.
