Pairing and the password

Two separate things. Pairing happens once, when you set up a new computer. The password decides who may drive a computer, every time someone connects.

First: which computer is which

The one at risk is the client (Kali), because it is the one being driven. The person at the laptop already owns the laptop. So the client decides who may drive it.

1 · Pairing — once, for a new computer

What it is

Two computers running mouse-rs only trust each other if they share a long hidden key, the shared secret (32 random characters). Without it, a stranger's mouse-rs on the same network can't even start talking to yours.

Before pairing existed, you had to copy those 32 characters by hand from one computer to the other. Pairing does that copy for you, safely, using a short 6-digit code instead.

How to do it
  1. On the laptop (has the mouse): Settings → Security & pairing → Pair a new device. It shows a code like 482 913 for 5 minutes.
  2. On the new computer: type that code into Pair with a code and press Pair.
  3. Done. The new computer now has the secret, and the two find each other by themselves from then on.
You don't need it today. Your laptop and Kali already share the secret. That is why the main window no longer shows pairing once a computer is paired. It's for a buyer setting up for the first time, or for adding a third computer. It is always in Settings → Security & pairing.

Why it's safe

The code is never sent over the network. Each side only proves it knows the same code. Someone listening learns nothing. Someone guessing gets 3 tries, then the code is gone and a new one is needed. A code works once.

2 · The password — who may drive this computer

Set on

Kali (the client)

Settings → Security & pairing → Set a password. Letters, numbers and symbols are fine, at least 4 characters.

Typed on

The laptop (the server)

When Kali asks, a password box appears on the laptop's main window. Type it there and press Connect. You type with the keyboard you are already using.

What a stranger on the same network sees

Say 100 people share an office network and 10 run mouse-rs. If one of them has paired with your Kali, then without a password they could drive it. With a password, their laptop shows the box, they don't know the password, and Kali refuses them.

Two switches, one password

Switch on KaliDefaultWhat it does
Ask at the login screenOnBefore anyone has logged in to Kali, the laptop must type the password to type into Kali's login screen. Turning login-screen sharing on asks you to set a password first.
Ask when someone is logged in hereOffThe same check during normal use. While it is off, Kali shows a reminder once a day: Set a password · Not now · Don't show this again.

How often you type it

Once each time mouse-rs starts on the laptop. After that the laptop remembers it, so a Wi-Fi drop or sleep reconnects without asking.

Wrong passwords

✗✗✗ →locked 1 hour→ ✗✗✗ →locked 2 hours→ then 4 h, 8 h…

While locked, Kali refuses even the right password. One correct password resets the count. Kali keeps the count, so a guesser can't get around it by switching computers.

Changing it, turning it off, or forgetting it

  1. Change: on Kali, Settings → Security & pairing → type the new password twice → Change password.
  2. Turn off: on Kali, switch off Ask when someone is logged in here and/or Ask at the login screen.
  3. Forgot it: sit at Kali and set a new one. No old password is asked for. Being at the computer is the proof.
  4. Login screen: after a change, Kali updates its login-screen copy by itself. Kali asks for its own computer password through the usual system prompt. No commands to type.
