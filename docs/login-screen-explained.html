Yes — it becomes a real system service.

The same kind of thing as NetworkManager or cron on this machine: started by the system at boot, running before anyone logs in, not tied to any person's account. It does not wait for you, so it is already there when the password box appears.

What changes at boot

Before

  • Power onKernel, then system services start
  • SDDM shows the password boxmouse-rs is not running
  • Nothing to type with You plug a keyboard into this machine, just for the password
  • You log inXFCE session starts
  • Autostart finally runs mouse-rs The shared keyboard works — one step too late

After

  • Power onKernel, then system services start
  • mouse-rs starts here As a system service, alongside the others. It connects to the laptop on its own
  • SDDM shows the password boxmouse-rs is already connected
  • You type from the laptop No second keyboard. Nothing to plug in
  • You log in The service steps aside, your own copy takes over

"Like other services" — exactly which ones

These are real services on this machine. The new one is listed the same way, started at the same point, by the same mechanism.

Same multi-user.target as NetworkManager and cron — meaning it is up before the login screen is even drawn.

Why it steps aside when you log in

Once you are logged in, your own mouse-rs starts too. If both kept running you would have two copies receiving the same keystrokes, and every letter would be typed twice. So exactly one runs at a time.

Login screen

Runs as the system. Keyboard and mouse only — no clipboard, no panel
→

Hand-over

→

Log out and it reverses: your copy ends with the session, the service starts again, and the login screen has the shared keyboard once more.

Is it a settings change?

Not a tick-box in the panel — it needed new code, because the old way could never have worked. Previously mouse-rs typed by talking to your X server, which does not exist until you have logged in. It now talks to the kernel instead, which is running the whole time. That is the actual change; the service is just what starts it.

For you it is three commands, once. After that it is permanent and survives reboots on its own.

# 1. Check it works while you still have a terminal to see errors in.
#    Put the cursor in a text editor — it types `mouse-rs ok`.
sudo ./target/release/mouse-rs greeter-selftest

# 2. Install the service.
sudo ./target/release/mouse-rs greeter-install

# 3. Start it now instead of waiting for a reboot.
sudo systemctl start mouse-rs-greeter

Then log out and try the password from the laptop. To undo all of it: sudo mouse-rs greeter-uninstall

What you are agreeing to

It can accept keystrokes before anyone has logged in.

That is the whole point — but it is worth saying plainly. Anything on your network that holds the shared secret can type at this machine's login screen. That secret is now the thing standing between the network and your password prompt.

It is off until you run the install command, the secret file is readable only by root, and the service is locked down to the network, its own folder and the one device it needs.

Two smaller things. It sends key positions, not letters, so the keyboard layout set at the login screen decides what appears — normal ASCII on a US layout is fine. And /etc/mouse-rs/config.json is a copy, so re-run the install after changing the shared secret or the laptop's address.
