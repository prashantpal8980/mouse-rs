B72 — Windows "Start at login as administrator" not changed
The task runs mouse-rs.exe from %USERPROFILE%\mouse-rs, which an ordinary program can write to. Anything that swaps the exe gets admin rights at the next logon, with no prompt. I didn't change it: the fix moves where the elevated copy lives and how it updates, can only be tested on Windows, and your laptop is off.		 A. Ship 1.0 as it is. The option is off by default, and Windows asks once before turning it on. Microsoft doesn't treat this as a security boundary. Fix in 1.1 by copying the exe to Program Files and pointing the task there.

B. Hide the toggle for 1.0. Simple and safe, but it brings back R20: crossing fails while an admin window is in front.

C. Build the Program Files copy tomorrow and test it on the laptop before release.		 yes
I'd pick A and list it in the release notes. To confirm the premise, run icacls "%USERPROFILE%\mouse-rs" on the laptop. If your user shows (F) or (M), the issue is real.
B65 — crash and PIN-prompt tampering fixed
The client signs its PIN refusal with the pairing key (new proof field). The computer with the mouse ignores unsigned refusals, and the lockout time is clamped so it can't overflow.		 The minimal fix was the clamp alone, which stops the crash. But anyone who knew a paired device ID could still wipe a typed PIN and put any name in the PIN prompt. FYI
An old client's refusal doesn't show the PIN prompt. That only matters while one computer is still on test15.
B70 — replayed UDP mouse-motion message fixed
The message (MRH2) now carries a counter that only goes up, and is accepted only from the IP the TCP link comes from.		 Checking the IP alone stops attackers using their own address, but not one faking the client's. FYI
An old client's motion message is ignored, so motion between an old and a new build goes over TCP. It still works, just with a little more delay on Wi-Fi.
B73 — test releases signed with the real key fixed
latest.json now carries a signed "channel". release.sh and sign-release.sh default to release, and fake-release.sh uses test. Release builds accept only release; test builds accept both.		 Use a separate signing key for rehearsals. Cleaner, but it means managing a second key, and the test builds already installed trust only the real one. FYI
Important for launch: sign the 1.0 release with release.sh or sign-release.sh, which add the channel. A hand-written latest.json without it would be ignored by every release install.
B66 — peer reading files never shared fixed
A peer's file list loses any path on this computer, both on arrival and when history reloads. This computer serves only files it offered itself.		 None worth taking: no legitimate case needs a peer to name a path on this computer. no
B67 / B69 — cache overwrite, disk filling fixed
  • A stream is written to disk only if this computer asked for it, and only if it matches the size in the offer.
  • A stream that runs past its length is stopped and deleted.
  • A file the cache already holds is never replaced by one checked only by length.
  • Totals no longer wrap, so a peer can't slip a huge set under the "ask first" limit.
 Also age out leftover partial files. I left that out: those partials exist so an interrupted transfer can resume, and a peer can no longer create them uninvited. no
B68 — received-files folder overwrite fixed
When notes (2) … notes (9999) are all taken, that one file is skipped, with a log line. The fallback copy can never overwrite.		 Use a random suffix instead, so the file always lands. The behavior is only reachable on purpose, so I kept it simple. no
B71 — log upload fallback fixed
The fallback address is recorded only after the server has proved the pairing key.		 Remove the fallback altogether. It's your dev tool, so I kept it working. no
B74 — one silent connection froze the hub (new) fixed
The audit had deferred this one. I confirmed it with a test that fails on the old code: any device on the network could freeze input for up to 20 s, again and again. Logins now run beside the hub, at most 16 at once; further connections are dropped until one finishes.		 Shorten the timeout instead. That shrinks the freeze but doesn't remove it. FYI
This is the biggest change tonight, inside run_server. All 126 network tests pass, but please give connecting and switching computers a normal try.

Not done (hardening notes from the audit, not bugs)

  • Log upload token: it is derived from a public default secret, so it authenticates nothing. Dev-only.
  • Windows firewall rule: it allows the exe on every network profile. Limit it to private and domain networks.
  • Greeter install: it copies current_exe() by path after polkit, and .new follows symlinks. Root-only paths, so not exploitable today.
  • Replayed discovery beacon: it can add a candidate address. Harmless now that both B71 and the handshake check the pairing key.
  • Images in the hub relay: the 256 KB image cap isn't enforced there.
  • Windows file names: reserved names like CON and NUL aren't mapped to safe ones.
  • Signed update descriptions: they have no expiry, so an old one can be replayed to hide a newer update.

I suggest these for 1.1; none blocks the launch. The full list is in ~/security-audit-skill/mouse-rs/run-1/REPORT.md, section 6.
