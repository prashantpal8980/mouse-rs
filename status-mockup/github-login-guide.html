Why you have to do this part

Logging in proves to GitHub that you own the account prashantpal8980. That needs your GitHub password (and 2FA code, if you use one), which only you should type. Claude can't do it, and shouldn't.

Once you're logged in, gh keeps a login token on Kali. Claude uses that token through the gh and git commands, without ever seeing or printing it.

The steps

1

Open a normal terminal on Kali

Use the regular Kali terminal app, not the Claude window. The login asks you questions and waits for Enter, and Claude's ! shortcut can't answer questions. You saw this happen with sudo earlier.

First check that gh is found:

gh --version
kalip@kalip:~$ gh --version gh version 2.102.0 (2026-09-30)

If it says command not found, run ~/.local/bin/gh wherever these steps say gh, or open a new terminal window.

2

Start the login

gh auth login --hostname github.com --git-protocol https --web

What you'll see, and what to answer:

kalip@kalip:~$ gh auth login --hostname github.com --git-protocol https --web ? Authenticate Git with your GitHub credentials? Yes ← press Enter (Yes is the default) ! First copy your one-time code: ABCD-1234 ← yours will differ; note it down Press Enter to open https://github.com/login/device in your browser... ← press Enter
Leave this terminal open. It waits until you finish in the browser, then continues by itself.
3

Approve in the browser

A browser tab opens at github.com/login/device. If none opens, go to that address yourself.

https://github.com/login/device
Device Activation
Enter the code displayed on your device
ABCD–1234

Continue
  1. If GitHub asks you to sign in, sign in as prashantpal8980. Check the account picture in the top right; if it's a different account, sign out first.
  2. Type the 8-character code from the terminal and click Continue.
  3. On the next page, "GitHub CLI wants to access your account", click Authorize github. You may be asked for your password or 2FA code again.
  4. You'll see "Congratulations, you're all set!" You can close the tab.

Back in the terminal, it finishes like this:

✓ Authentication complete. - gh config set -h github.com git_protocol https ✓ Configured git protocol ✓ Logged in as prashantpal8980
4

Let git use this login

This lets plain git push use the same login. It prints nothing when it works.

gh auth setup-git
5

Check it, then tell Claude

gh auth status
github.com ✓ Logged in to github.com account prashantpal8980 (keyring) - Active account: true - Git operations protocol: https - Token: gho_************************************ - Token scopes: 'gist', 'read:org', 'repo'

If you see Logged in and 'repo' in the scopes, you're done. Come back to Claude and type "gh login done".

Don't paste the token into the chat. gh auth status hides it with stars; keep it that way. Claude doesn't need it.

What Claude can and can't do once you're logged in

Will do, when you ask

  • Commit work and push it to GitHub
  • Create branches, pull requests and releases
  • Open and read issues
  • Check whether the copy on GitHub matches Kali

Won't do

  • Push without you asking. Commits and pushes happen only on your request.
  • Force-push over GitHub history or delete the repo, unless you say so explicitly
  • Show, copy or log your GitHub token
  • Push anything containing the mouse-rs shared secret. Every push gets checked first.

If something goes wrong

The browser didn't open

Open https://github.com/login/device yourself in any browser, even on the laptop, and enter the code. The terminal is still waiting and continues on its own.

"The code has expired" or the terminal gave up

The code lasts 15 minutes. Press Ctrl+C in the terminal and run step 2 again to get a new code.

I logged in with the wrong GitHub account

Run gh auth logout --hostname github.com, sign out on github.com in the browser, then start again at step 2.

It asks about a keyring or password store

If Kali's keyring isn't available, gh saves the token in ~/.config/gh/hosts.yml, readable only by you. Both are fine.

How do I undo all of this later?

On Kali, run gh auth logout. On GitHub, go to Settings → Applications → Authorized OAuth Apps → GitHub CLI → Revoke. Either one stops Claude from pushing.

Why HTTPS and not my SSH key?

Your SSH key (~/.ssh/id_ed25519) isn't registered with your GitHub account; GitHub rejected it when Claude tested it. HTTPS through gh needs no extra setup. You can add the key later at github.com → Settings → SSH keys if you like.

A note about "public"

You chose a public repo, so anyone can read the code. There's no LICENSE file, which by default means people may look but have no right to copy or reuse it. That still protects you as the seller.

To switch it to private later, run gh repo edit prashantpal8980/mouse-rs --visibility private --accept-visibility-change-consequences, or ask Claude.
